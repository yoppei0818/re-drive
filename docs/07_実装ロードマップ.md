# 07｜実装ロードマップ

## Phase 0｜技術検証

- [x] Expoで位置情報を取得する
- [x] 地図に現在地とPolylineを表示する
- [x] FastAPIからGoogle Routes APIを呼ぶ
- [x] Maps URLでGoogle Mapsへ経路を渡す
- [x] API利用量と概算コストを確認する

**完了条件：** 固定の経由地を使い、実機で周回ルートを表示してGoogle Mapsへ渡せる。

## Phase 1｜MVPコア

- [ ] 条件入力画面
- [ ] 候補中間地点の生成
- [ ] 希望時間に近い候補の抽出
- [ ] 特徴量抽出と難易度スコア
- [ ] 候補3案の地図・カード表示
- [ ] エラー・候補不足時の再試行UI

**完了条件：** 現在地と希望時間から、再現可能な難易度付きルート候補を取得できる。

## Phase 2｜アカウントとデータ

- [ ] Supabase Auth
- [ ] DB migration
- [ ] RLS policyとテスト
- [ ] ユーザー設定
- [ ] ルート保存
- [ ] 運転履歴

**完了条件：** ユーザー間でデータが分離され、保存した設定と履歴を復元できる。

## Phase 3｜AI説明

- [ ] 特徴量から評価理由を生成する
- [ ] 構造化出力を検証する
- [ ] テンプレート説明へのフォールバックを実装する
- [ ] プロンプトとモデルのバージョンを管理する

**完了条件：** AIが失敗しても難易度と基本説明を表示でき、AIが地理的事実や難易度を上書きしない。

## Phase 4｜公開準備

- [ ] 利用規約、プライバシーポリシー、免責表示
- [ ] 位置情報の権限説明
- [ ] App Store / Google Playのデータ申告
- [ ] 外部API規約と表示要件の確認
- [ ] 監視、アラート、費用上限
- [ ] 実走テスト計画とフィードバック導線
- [ ] アカウントと履歴の削除導線

**完了条件：** 安全表示、データ取扱い、障害時対応をレビューできる状態になっている。

## MVP後

- 累計運転時間、走行距離、回数の集計
- 運転履歴の期間別表示
- 個別履歴の地図、ルート特徴、任意メモ
- 過去条件や保存ルートの再利用
- 必要性を検証した後の道路・交差点フィードバック

## フェーズ運用

- アカウント、保存、履歴は最終的なMVPスコープに含む
- Phase 0〜1では、まずルート提案の技術的成立性と価値を検証する
- 各フェーズの完了条件を満たすまで、次フェーズ固有の機能を必須にしない
- 外部APIの仕様、料金、規約は実装時点で再確認する
